## Introduction

The Node Group Analysis page provides a cluster-wide and node-group-level view of Kubernetes infrastructure efficiency. It enables teams to analyze node utilization patterns, identify waste, detect operational risks, and understand optimization opportunities across Kubernetes environments.

The page aggregates metrics and analytics for node groups including:

- CPU utilization
- Memory utilization
- Kubernetes resource requests
- Allocated versus utilized capacity
- Infrastructure costs
- Optimization potential
- Risk indicators
- Rightsizing recommendations

## Accessing the Node Group Analysis Page

Node Group Analysis can be accessed from:

**Infrastructure → Kubernetes → Nodes → Node Group Analysis**

## Node Group Analysis Dashboard

The dashboard provides a consolidated view of all Kubernetes node groups and their optimization status.

## Key Insights Provided

The Node Group Analysis page helps teams answer critical operational and financial questions such as:

- Which node groups are overprovisioned?
- Which node groups are at risk of CPU or memory exhaustion?
- Where is infrastructure capacity being wasted?
- Which node groups should be resized?
- Which node groups are operating inefficiently?
- What cost savings opportunities exist?
- Are Kubernetes requests significantly higher than actual utilization?

## Understanding Resource Waste

One of the most significant sources of Kubernetes infrastructure waste comes from the mismatch between:

- Kubernetes resource requests
- Actual workload utilization

Kubex visualizes this inefficiency directly in the utilization and request charts.

### High Requests vs Low Utilization

In many environments, application teams configure CPU and memory requests conservatively to avoid performance issues. While this provides workload protection, it often results in substantial over-allocation of infrastructure resources.

**Common scenarios include:**

- CPU requests significantly higher than actual CPU consumption
- Memory requests greatly exceeding observed usage
- Large node groups operating at low average utilization
- Idle capacity reserved but never consumed
- Cluster autoscaler unable to scale down due to inflated requests

**This leads to:**

- Increased cloud costs
- Poor node density
- Lower workload packing efficiency
- Unnecessary infrastructure expansion
- Reduced ROI on Kubernetes infrastructure

Kubex highlights this waste by comparing:

- Requested resources
- Allocated resources
- Actual utilization

The visual gap between request levels and actual utilization provides a clear indication of optimization potential.

## Risk Identification for Node Groups

Kubex identifies operational and capacity risks that may impact cluster stability, workload performance, or infrastructure resiliency.

### Types of Risks Identified

#### Capacity Risks

Node groups approaching sustained high utilization may experience:

- CPU saturation
- Memory exhaustion
- Pod scheduling failures
- Increased workload latency
- Resource contention

Kubex flags node groups with elevated utilization or insufficient headroom.

#### Resiliency Risks

Node groups with insufficient redundancy or excessive consolidation may create resiliency concerns such as:

- Single points of failure
- Limited failover capacity
- Reduced cluster fault tolerance
- Insufficient scaling headroom

#### Cost Risks

Kubex identifies node groups with:

- Persistent low utilization
- Excessive overprovisioning
- Large request-to-utilization gaps
- Inefficient instance sizing
- Unnecessary infrastructure expansion

These conditions represent avoidable infrastructure spend.

#### Scheduling Risks

Improperly sized nodes or fragmented capacity may create scheduling inefficiencies including:

- Pending pods
- Resource fragmentation
- Inefficient workload placement
- Autoscaling instability

## Cost Savings Opportunities

Kubex quantifies infrastructure savings opportunities by analyzing:

- Underutilized nodes
- Oversized instances
- Resource waste
- Idle reserved capacity
- Kubernetes request inflation
- Consolidation opportunities

### Common Savings Strategies

#### Rightsizing Nodes

Reducing oversized node instance types based on actual workload consumption.

#### Consolidating Node Groups

Reducing excess infrastructure by consolidating workloads onto fewer nodes.

#### Optimizing Kubernetes Requests

Aligning requests closer to actual utilization to improve scheduling density.

#### Improving Bin Packing

Increasing workload density while maintaining operational safety margins.

#### Eliminating Idle Capacity

Removing unused nodes or reducing autoscaler minimums.

### Business Impact

Organizations commonly achieve:

- Reduced Kubernetes infrastructure costs
- Improved cloud efficiency
- Better workload density
- Higher infrastructure utilization
- Improved cluster scalability
- Faster identification of inefficiencies
