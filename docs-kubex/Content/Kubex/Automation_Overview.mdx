## Automating Container Recommendation

The Kubex Automation Controller provides intelligent, policy-driven automation for managing container resource configurations in Kubernetes clusters. It safely and efficiently optimizes workload resources based on Densify's optimization recommendations while respecting your operational constraints.

### Key Features

<ul>
  <li><strong>Automated Resizing</strong>: Dynamic CPU and memory optimization based on actual usage patterns</li>
  <li><strong>Safety-First Approach</strong>: Multi-layered validation including HPA awareness, LimitRange compliance, ResourceQuota checking, and PodDisruptionBudget respect</li>
  <li><strong>Policy-Driven</strong>: Configurable automation rules for downsizing, upsizing, and constraint handling</li>
  <li><strong>Flexible Targeting</strong>: Multiple scope configurations for different automation behaviors across cluster regions</li>
  <li><strong>Enterprise Ready</strong>: RBAC integration, audit trails, and GitOps compatibility</li>
</ul>

### Getting Started

There are a few steps to enable automation for your environment:

<ol start="1">
  <li>
    <strong>Deploy the Kubex Automation Controller</strong>: Use the Helm chart to deploy the controller and mutating admission webhook. All required files and detailed instructions are provided in the [
    <a href="https://github.com/densify-dev/helm-charts/tree/master/charts/kubex-automation-controller"> Kubex Automation Controller Helm Chart </a>
    ].
  </li>
  <li>
    <strong>Configure Policies</strong>: Define your automation behavior through the configuration files. The policy settings determine which workloads are optimized and how the automation behaves. 
    <br/>
    See the [
    <a href="https://github.com/densify-dev/helm-charts/blob/master/charts/kubex-automation-controller/docs/Getting-Started.md"> Getting Started Guide </a>
    ] for detailed configuration instructions.
  </li>
  <li>
    <strong>Optional Kubex Management Layer</strong>: 
    <p><strong>Important:</strong> The filter and enable/disable controls inside Kubex only work when the Helm values set <code>remoteEnablement: true</code>. When this flag remains <code>false</code> (the default), automation scope is managed exclusively through the Helm chart configuration.</p>
    <p><strong>Both conditions must be met</strong>: the workload must match your Helm-defined scope (namespace and optional <code>podLabel</code>) <em>and</em> be enabled in Kubex. If either side is missing, automation does not run for that container.</p>
    <p>Right-click in the container tree view to select <strong>Enable Automation</strong> or <strong>Disable Automation</strong> for workloads that already match your Helm scope.</p>

### Monitoring Automation Activity

If you need to confirm which clusters have automation deployed—or check the health of those deployments—open the <a href="/docs-kubex/Content/Kubex/Automation_Tab">Automation status</a> page for detailed telemetry and recent change history. 

The <strong>Container Overview Summary</strong> page shows how many container manifests are currently enabled for automation and how many have been actively automated over the past 7 and 90 days. 

Each metric is interactive—clicking any of the numbers drills into the filtered list of containers that make up that count so you can review the specific workloads behind the summary.

<p>

</p>
<p>

</p>

### Automation Policies

Automation policies define how the Kubex Automation Controller optimizes your workloads. These policies are configured through the Helm chart values and determine which resources are automatically optimized, under what conditions, and with what constraints.

For detailed information on configuring automation policies, including policy structure, safety rules, and advanced configurations, see the [Policy Configuration Guide](https://github.com/densify-dev/helm-charts/blob/master/charts/kubex-automation-controller/docs/Policy-Configuration.md) in the Helm chart documentation.
