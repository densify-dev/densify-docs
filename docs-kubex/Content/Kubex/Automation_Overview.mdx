## Automating Container Recommendation

The Kubex Automation Engine provides intelligent, policy-driven automation for managing container resource configurations in Kubernetes clusters. It safely and efficiently optimizes workload resources based on Kubex's optimization recommendations while respecting your operational constraints.

### Key Features

<ul>
  <li><strong>Automated Resizing</strong>: Dynamic CPU and memory optimization based on actual usage patterns</li>
  <li><strong>Zero-Downtime Optimization</strong>: In-place container resizing without pod restarts (Kubernetes 1.33+) with automatic fallback to pod eviction</li>
  <li><strong>Safety-First Approach</strong>: Multi-layered validation that is HPA-aware, enforces LimitRange and ResourceQuota policies, respects PodDisruptionBudgets, and validates node capacity before applying changes</li>
  <li><strong>Smart Pause Control</strong>: Annotation-based pausing for learning periods after application changes or applying permanent exclusions</li>
  <li><strong>Policy-Driven</strong>: Configurable automation rules for downsizing, upsizing, and constraint handling</li>
  <li><strong>Flexible Targeting</strong>: Multiple scope configurations for different automation behaviors across cluster regions</li>
  <li><strong>Enterprise Ready</strong>: RBAC integration, audit trails, and GitOps compatibility</li>
</ul>

### Getting Started


Use the Helm chart to deploy the [Kubex Automation Engine Helm Chart](https://github.com/densify-dev/helm-charts/blob/master/charts/kubex-automation-engine/docs/Getting-Started.md).

### Monitoring Automation Activity

If you need to confirm which clusters have automation deployed—or check the health of those deployments—open the <a href="/docs-kubex/Content/Kubex/Automation_Tab">Automation status</a> page for detailed telemetry and recent change history. 

The <strong>Container Overview Summary</strong> page shows how many container manifests are currently enabled for automation and how many have been actively automated over the past 7 and 90 days. 

Each metric is interactive—clicking any of the numbers drills into the filtered list of containers that make up that count so you can review the specific workloads behind the summary.

### Automation Policies and Configuration

Automation policies define how the Kubex Automation Engine optimizes your workloads. These policies are configured through the Helm chart values and determine which resources are automatically optimized, under what conditions, and with what constraints.

**Creating Automation Strategies and Policies:**
- See the [Configuration Reference](https://github.com/densify-dev/helm-charts/blob/master/charts/kubex-automation-engine/docs/Configuration-Reference.md) for complete details on policy structure, targeting rules, and optimization strategies.

**Safety Controls and Advanced Configuration:**
- The [Advanced Configuration Guide](https://github.com/densify-dev/helm-charts/blob/master/charts/kubex-automation-engine/docs/Advanced-Configuration.md) covers safety controls, pausing automation, and advanced deployment scenarios.
