## Introduction

The Node Detail page provides detailed analysis and optimization insights for individual Kubernetes nodes.

This page enables operators to:

- Analyze node utilization patterns
- Identify inefficient resource allocation
- Detect operational risks
- Understand workload density
- Evaluate optimization opportunities
- Investigate node-specific performance behavior

## Accessing the Node Detail Page

Node details can be accessed from:

**Infrastructure → Kubernetes → Nodes → Node Details**

Direct URL:

```
https://sandboxuat.densify.com/kubex/nodes-tree/tree-item?fullPath=Nodes+%28Last+Day%29&level=1&tnodeId=0&type=ROOT&tabGroupNode=node-detail&tabGroup2=overview
```

## Understanding Node Efficiency

Kubex evaluates node efficiency by comparing:

- Total available node capacity
- Allocated Kubernetes requests
- Actual workload utilization

This analysis helps identify nodes that are:

- Overprovisioned
- Underutilized
- Overloaded
- Fragmented
- Inefficiently packed

### Waste Identification

One of the most common inefficiencies occurs when:

- CPU and memory requests are significantly higher than actual utilization
- Nodes reserve large amounts of unused capacity
- Workloads consume only a fraction of allocated resources

The charts on the node page clearly visualize these inefficiencies.

### Examples of Waste

- Nodes running at 20–30% CPU utilization while requests reserve 70–90% capacity
- Memory requests reserving large amounts of unused RAM
- Nodes blocked from consolidation due to inflated requests
- Cluster autoscaling prevented from reducing infrastructure footprint

Kubex highlights these patterns to support safer optimization decisions.

## Node Risk Analysis

Kubex continuously evaluates operational risks at the node level.

### CPU Risk

Nodes with sustained high CPU utilization may experience:

- Workload throttling
- Scheduling delays
- Application latency
- Resource contention

### Memory Risk

Nodes approaching memory saturation may experience:

- OOMKills
- Pod evictions
- Node instability
- Performance degradation

### Scheduling Risk

Kubex identifies nodes affected by:

- Resource fragmentation
- Imbalanced workload placement
- Excessive reserved capacity
- Poor bin-packing efficiency

### Stability Risk

Node instability indicators may include:

- Frequent workload churn
- Saturation spikes
- Persistent high utilization
- Capacity exhaustion trends

## Optimization Recommendations

Kubex provides actionable recommendations to improve node efficiency and reduce infrastructure costs.

### Types of Recommendations

**Node Rightsizing**

Adjust node instance types based on observed utilization patterns.

**Workload Rebalancing**

Improve workload distribution across the cluster.

**Request Optimization**

Reduce excessive Kubernetes requests that limit scheduling density.

**Consolidation Opportunities**

Move workloads to fewer nodes while maintaining operational safety.

**Autoscaling Improvements**

Optimize autoscaler configuration to reduce idle capacity.

Kubex identifies:

- Underutilized nodes

- Increase node utilization

## Charts and Analytics

The Node Detail page includes rich visualizations that expose node behavior and optimization opportunities.

### Utilization Charts

Charts display:

- CPU utilization over time
- Memory utilization over time
- Kubernetes requests
- Resource allocation patterns

These visualizations make it easy to identify:

- Persistent underutilization
- Excess reserved capacity
- Saturation trends
- Request inflation

### Request vs Utilization Analysis

A key optimization insight comes from comparing:

- Requested resources
- Actual consumed resources

Large gaps between these metrics indicate wasted infrastructure capacity and opportunities for:

- Rightsizing
- Better workload packing
- Reduced cloud spend
- Improved cluster efficiency
