The Kubex Automation Engine uses layered safety controls to ensure that recommendation-driven resource changes are applied only when the relevant policy and runtime checks pass. Controller-side proactive execution is fail-closed when required safety checks or webhook health conditions are not satisfied. If the admission webhook is unavailable, Kubernetes can continue pod creation without Kubex mutation.

## Safety Controls

The engine combines multiple protections:

- Webhook health gating for controller-side automation
- `HPA` and `VPA` compatibility filters
- `LimitRange` and `ResourceQuota` checks
- Node allocatable capacity and headroom checks
- Pod readiness and workload availability checks
- Protected namespace patterns
- Policy scope, selectors, and workload-type filters
- Pause and container-exclusion annotations

When a check fails, the affected resize action is blocked or filtered, and the reason is surfaced through workload events, controller logs, rightsizing summaries and in the Kubex UI.

## Global Runtime Controls

`GlobalConfiguration` is used for cluster-wide behavior:

- Recommendation refresh cadence
- Pod rescan cadence
- Mutation log and snapshot upload intervals
- Automation on/off switch
- Webhook health thresholds
- Protected namespace patterns

## Pause and Control Patterns

Operational pause options include:

- Global disable through `globalConfiguration.automationEnabled`.
- Targeted workload inclusion and exclusion through policy scopes, selectors, workload types, and pause controls.
- Annotation-based pause: pause automation for a pod, workload, or namespace during a learning or stabilization period using `rightsizing.kubex.ai/pause-until`.

## Execution Paths

The engine can apply rightsizing via:

- In-place resize when supported by cluster version and policy
- Eviction-based resize fallback when in-place resizing is unavailable or not allowed

## Diagnostics for Runtime Safety

Useful commands:

```bash
kubectl get globalconfiguration global-config -o yaml
kubectl get events -A --field-selector reason=PrecheckFailed
kubectl logs -n kubex -l control-plane=controller-manager -c manager --since=10m | grep 'rightsizing summary'
```
