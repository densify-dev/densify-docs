You can use the following process to setup Microsoft Entra ID (formerly known as Azure AD). You need to register Kubex as a web application in your Microsoft Entra ID and then provide the following information to Kubex:

* Application (client) ID
* Directory (tenant) ID
* Client secret (password)

An auto-provisioning feature allows users to access the Kubex Console without needing to manually create user accounts in Kubex. Additional configuration is required as outlined in, [Creating User Groups for Users](#Create_groups). Contact [support@kubex.ai](mailto:support@kubex.ai) to enable the auto-provisioning feature.

### Register an Application

You must have permission to manage applications in Microsoft Entra ID. i.e. Application administrator or Application developer, etc.

1. Log into the Microsoft Entra ID portal. If you have access to multiple tenants, use the Directories + subscriptions filter in the top menu to switch to the tenant in which you want to register the application.
2. Navigate to Microsoft Entra ID > App Registrations > New registration.
<Accordion title="Figure: Creating a New Registration">
<Frame>![](/images/docs/WebHelp_Densify_Cloud/Content/Resources/Images/CiRBA_Administration_Guide/030000C6_329x191.png)</Frame>
</Accordion>
3. In the Register an application pane, enter the following information:

* The Name of the application (i.e. Kubex\_Connection)
* Specify who can use the application. You can leave the default setting, Accounts in this organizational directory only (Default Directory only – Single tenant).
* You do not need to add anything under the Redirect URI. You can configure the URIs in the next section.

4. Once you have entered the required information the Register button becomes available. Click Register to complete the process.
<Accordion title="Figure: Creating a New Registration">
<Frame>![](/images/docs/WebHelp_Densify_Cloud/Content/Resources/Images/CiRBA_Administration_Guide/030000C8.png)</Frame>
</Accordion>
5. Once you have completed the registration, you will be directed to the overview page for your new application registration.

New app registrations are hidden to other users by default. Refer to Microsoft.com for details on enabling your app registration for other users, if required.

#### Obtaining the Application and Directory IDs

1. In the Microsoft Entra ID portal, navigate to Microsoft Entra ID > App Registrations.
2. Select your new App Registration and copy the following values:

* Application (client) ID
* Directory (tenant) ID

You need to provide these values to Kubex to complete the authentication process.

### Configuring the URIs

A redirect URI is the location where the Microsoft identity platform redirects a user's client and sends back the security tokens after authentication.

1. In the Microsoft Entra ID portal, in App registrations, select your application registration.
2. Select Authentication from the side menu.
3. Under Platform configurations, click Add a platform and then choose Web applications > Web.
4. Under Redirect URIs, add the following URIs:
<Note>
These are examples only. Contact Kubex for the actual URIs.
</Note>



* https://\<instancename>.kubex.ai:443/redirect
* https://\<instancename>.kubex.ai:443/
* https://\<instancename>.kubex.ai:443/kubex
* https://\<instancename>.kubex.ai:443/openIdError

5. Click Add URI to add each entry. You should have a total of 4 URIs.
<Accordion title="Figure: Adding Redirect URIs">
<Frame>![](/images/docs/WebHelp_Densify_Cloud/Content/Resources/Images/CiRBA_Administration_Guide/030000CC.png)</Frame>
</Accordion>
6. Click Save to commit all your information.

### Obtaining the Credentials

The credentials generated here allow Kubex to authenticate as itself, requiring no interaction from the user at runtime.

A client secret is sometimes called an application password. It is a string value that Kubex can use in place of a certificate to identity itself.

1. In the Microsoft Entra ID portal, in App registrations, select your application registration.
2. Navigate to Certificates & secrets > Client secrets > New client secret.
3. Add a description for your client secret. i.e.Kubex-Client-Secret
4. Select an expiration for the client secret or specify a custom lifetime. Please note the following:

* Client secret lifetime is limited to 24 months, or less.
* Microsoft recommends that you set an expiration value of less than 12 months.
* You will need to renew the secret prior to the expiry date and provide the new value to Kubex each time the value expires.

5. Click Add to save your settings and to generate the client secret.
<Accordion title="Figure: Copying Client Secret Value">
<Frame>![](/images/docs/WebHelp_Densify_Cloud/Content/Resources/Images/CiRBA_Administration_Guide/030000CD.png)</Frame>
</Accordion>


Record the displayed value, as this value will not be displayed again once you leave this page and you need to provide this value to Kubex.

### Configuring the API Permissions for the Connection

In this section, you provide Kubex, now registered with the Microsoft identity platform with access to your own web API. You also provide the client app access to Microsoft Graph.

1. In the Microsoft Entra ID portal, select App registrations and then select your application registration.
2. Navigate to Manage > API permissions > Add a Permission > Microsoft Graph.
<Accordion title="Figure: Configuring the API Permissions">
<Frame>![](/images/docs/WebHelp_Densify_Cloud/Content/Resources/Images/CiRBA_Administration_Guide/03200049.png)</Frame>
</Accordion>
3. Choose ‘Delegated Permissions’. Microsoft Graph exposes many permissions, with the most commonly used permissions shown at the top of the list.
4. Under OpenId permissions, select:

* email--Allow Kubex to view the users’ email address;
* profile--Allow Kubex to view the users’ basic profile;

<Accordion title="Figure: Configuring the API Permissions">
<Frame>![](/images/docs/WebHelp_Densify_Cloud/Content/Resources/Images/CiRBA_Administration_Guide/03200050.png)</Frame>
</Accordion>


* Under GroupMember select:

* GroupMember.Read.All--Allow Kubex to read all user groups.

<Note>
If the auto-provisioning feature is enabled, you need to add this permission. If the auto-provisioning is not enabled you do not need this permission.
</Note>


<Accordion title="Figure: Configuring the API Permissions">

5. Under User select:

* User Read--should already be delegated. Allows Kubex to sign in and read user profile.

6. Click Add Permissions and choose Grant admin consent confirmation. Then click ‘Yes’ when prompted.

### Creating User Groups for Kubex Users

<Note>
If the auto-provisioning feature is enabled, you need to create these groups, otherwise you can skip these steps.
</Note>



The auto-provisioning feature allows users to access the Kubex Console without needing to manually create user accounts in Kubex. Once the feature is enabled, you must create groups in your Microsoft Entra ID that correspond to Kubex's user groups and add users to grant the required permissions.

Contact [support@kubex.ai](mailto:support@kubex.ai) to enable the auto-provisioning feature.

You need to create user groups that correspond to the commonly used Kubex user groups: KUBEX\_USER, KUBEX\_USER\_ADMIN, KUBEX\_AUDIT\_ADMIN, and KUBEX\_POLICY\_ADMIN.

1. Navigate to Manage > Groups. You will see the list of existing groups.
2. Click New group at the top of the list and configure the group settings:

* Group Type--Select "Security"
* Group name--Specify the name, KUBEX\_USER. Use this exact name (uppercase, underscore and no spaces) for your new group.
* Group description--Optional: Provide a description for this group.
* Membership type--Specify how users will be added to the group i.e. "Assigned".

3. Click Create to create the group.
4. Repeat the process to create a group for KUBEX\_USER\_ADMIN, KUBEX\_AUDIT\_ADMIN, and KUBEX\_POLICY\_ADMIN.


<Note>
These new user groups cannot be hidden groups.
</Note>



### Adding Kubex Users to Groups

Add the users to one or more groups. You can add users to all groups or add them to a specifc group , based on their requirements.

* KUBEX\_USER--Users with this role can access all features in the Kubex Console.
* KUBEX\_USER\_ADMIN--Users with this role can add, edit and remove Kubex user accounts through the user management dialog box.
<Note>
User management is not required within Kubex when Open ID is configured and the auto-provisioning feature is enabled.
</Note>

* KUBEX\_AUDIT\_ADMIN--Users with this role can create, edit or delete cloud audits, but cannot manage user accounts.
* KUBEX\_POLICY\_ADMIN--Users with this role can edit policies applied to cloud accounts or Kubernetes clusters.

1. You should now see these new groups appear in the list of all groups. Navigate to one of the groups created above (i.e.: KUBEX\_USER)
2. Click Add members at the top of the list and select the users to be added:
3. Click Add.
4. Repeat the process to add users to the other groups.
5. After any changes, existing users must log out and clear their browser before logging in again. This is required regardless of the type or version of browser you are using.

### Completing the Setup

You now need to provide the following information to Kubex to complete the setup:

* Application (client) ID;
* Directory (tenant) ID;
* client secret value

These settings are all configured for you by Kubex. Contact [support@kubex.ai](mailto:support@kubex.ai) for details.
